## Policy decisions
- Enabled iff `quota_enabled` true, or unset and tier public. Disabled ⇒ all hooks are P2.0 no-ops, no middleware added, no DB file (test `test_every_hook_passes_through_none_and_disabled`, `test_private_default_installs_nothing`; golden unchanged).
- Pessimistic money: `reserve` charges the estimate immediately (`spend + est <= cap` in one SQL UPDATE); `settle` swaps in actual exactly once (open→settled); `finalize`/expiry keep the estimate (open→charged). A reservation whose request never finalizes is therefore already paid; a late settle cannot refund.
- Endpoints are metered deny-by-default (`_EXEMPT_ENDPOINTS` is empty). Every metered endpoint is rate-limited and counted as free questions: ask, ask_stream and validate count 1; ask_compare counts one per model, plus 1 for the judge.
- IP keys: IPv4-mapped IPv6 addresses become IPv4, and other IPv6 addresses are keyed by their `/quota_ipv6_prefix` (64) network.
- The admit check looks only at **settled** spend in the request's pool (open reservations are upper-bound estimates). The hard guarantee stays in `reserve`, which is atomic and includes open reservations. If the cap refuses a request before its first answering round (answer, continue, regen, compare or review), the free question is refunded. A refusal after that round keeps the question, as do failures that are not refusals (for example a retrieval 502).
- Public tier: startup fails if `quota_trusted_proxies` is empty. The `/api/validate*` body-limit exemption applies only on the private tier.
- `_ReqState.open` is guarded by a per-request lock (test `test_open_handles_are_settled_or_closed_once_across_threads`; a race cannot be mutation-tested reliably).
- Free request order: kill switch → cap → rate limit → history trim → free count (visitor cookie AND client IP, all-or-nothing), so refusals never burn a question. Free questions get no web (`body.web=False` + `downgrades: free_tier_no_web`).
- BYOK: not counted against free questions, but rate-limited. Spend pools follow the user's decision: all server-key spend together is capped at `quota_site_cap_usd` ($5). Server-key calls made for BYOK requests (embedding, routing, Tavily) draw on `quota_byok_side_budget_usd` ($2), which is carved out of the cap; the budget is clamped into [0, cap]. Free requests get the remaining $3. So once free questions use up their share, BYOK keeps working until its own pool is gone, and the two pools never sum past the cap. Each request is checked against its own pool both at admit and at reserve. BYOK Tavily also has a per-visitor daily quota.
- A call is user-paid iff the request is BYOK and (purpose ∈ answer/continue/regen, or `kw["api_key"] == ctx.credentials.api_key`). **L1 coordination:** L1 must pass the user key in kwargs for any non-answer BYOK purpose, else it is metered as server-key (safe direction).
- Reservation size: the default model (`anthropic/claude-sonnet-5-5`, deployment max_tokens 128000) reserves about $1.3–1.9 per answer round (dominated by 128000 output tokens × $15/M). Under a $5 cap that is only about 3 concurrent free rounds. The public free model (DeepSeek v4-pro) is far cheaper. If the free tier stays on Sonnet, L3 or the operator should lower that deployment's max_tokens, or raise the cap.
- Pricing: `cost.estimate_cost` asked per 1M tokens (it rounds to 6 dp ⇒ embeddings priced $0 otherwise); unknown model ⇒ fallback $5/$25 per Mtok, never $0. Router groups mapped to the real model + deployment `max_tokens` via `app.state.settings`. Prompt estimate: 1 token/non-ASCII char, 1/3 per ASCII char.
- History trim: newest-first contiguous, ≤8 msgs and ≤20k chars; a message that does not fit ends the walk (single >20k message ⇒ empty history); leading assistant dropped.
- Body limit: Content-Length up front, chunked bodies counted; `/api/validate*` exempt (not registered on public).
- `CF-Connecting-IP` used only when the socket peer is in `quota_trusted_proxies`.
