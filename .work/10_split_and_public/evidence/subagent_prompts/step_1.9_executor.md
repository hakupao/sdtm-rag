## Design (revised v0.2 — implement this)
Identity of every chroma dir = `kb_fingerprint` in its stamp + a gate marker file (e.g. `kbsync_gate.json`: fingerprint, ref, A commit, image tag, baseline/candidate CDISC counts, diff question ids, timestamp, verdict). No SHA-based logic.

1. **Orchestration script** `deploy/kbsync/kbsync.py` (stdlib only; runs in the job container, NOT in the image; NOT in sdtm-rag.yml path filter — keep it that way). All paths (data root, image, etc.) are arguments → pytest on tmp dirs. Subcommands roughly: `detect`, `candidate` (build+gate), `predeploy-check`, `swap`, `restore`, `prune`. Docker calls go through one small wrapper so tests can fake it.
2. **Detection workflow** `.gitea/workflows/kb-sync.yml`: `schedule` daily + `workflow_dispatch` (input `ref`, default = newest `kb-*` tag of https://github.com/hakupao/sdtm-pedia via `git ls-remote --tags`; validate ref format). Checkout this repo with submodules, then `git -C vendor/sdtm-pedia fetch --depth 1 origin tag <ref>` (or the ref) + checkout. Compute fingerprint with `scripts/kb_freshness.kb_fingerprint` (python3 in job). Compare to prod stamp (read via `docker run --rm -v <data>/chroma:/c:ro <current prod image> cat` or busybox — do not open chroma). Equal → no-op, exit 0 with summary. A gated candidate dir for that fingerprint already exists → no-op. Same `concurrency` group as deploy (`sdtm-rag-deploy`).
3. **Candidate + gate** (same workflow, fingerprint differs): `docker build` a LOCAL-ONLY candidate image (tag e.g. `sdtm-rag-kbcand:<fp12>`, never pushed) from the checkout with the new KB → KB at native path, no overrides. Copy prod chroma → `<data>/chroma_cand_<fp12>` (via `docker run` cp -a). Copy prod meta.yaml → candidate meta dir. Baseline = CDISC 140q retrieval-only (`eval.run_eval eval/test_set_v3.yml --retrieval-only --hybrid --structured-lookup`) with the CURRENT prod image on the candidate copy BEFORE reingest (in-run baseline; no stored baseline). Then candidate image: `scripts.ingest` (KB collection only) + `scripts.build_meta` on the copy, then the same eval. Container mounts: `data/` read-only, candidate chroma and candidate meta overlaid read-write at their native paths (`/app/data/chroma`, `/app/data/meta`) so a missing overlay fails instead of writing prod; output dir for eval json under the candidate dir. `--memory 1536m`. Assert candidate stamp fingerprint == detected fingerprint (catches re-ingesting the old KB). Gate: per-question recall regressions ≤ 1 (define precisely from run_eval output; read eval/compare_runs.py if useful). Pass → write marker verdict=PASS. Fail → marker verdict=FAIL, move dir to `chroma_failed_<fp12>_<ts>` (never delete; rule B), workflow fails. CDISC only, never study eval. Summary/log shows only counts + question ids. Remove candidate image at end.
4. **Deploy extension** (`sdtm-rag.yml`, separate commit, AFTER 1–3 are committed): before compose up, compute the target image's KB fingerprint (`docker run --rm --entrypoint python <img> -c ...`; old images without `scripts.kb_freshness` → treat as unknown). Compare with prod stamp (string compare only).
   - equal → unchanged behaviour.
   - differs → look for `chroma_cand_<fp>` with PASS marker, or retained `chroma_prev_<fp12>_*` (for rollback). Found → `swap`: stop api+ui, verify the non-KB collections (names + counts) of candidate == prod (read via the target image, prod stopped) else fail, rename prod chroma → `chroma_prev_<oldfp12>_<ts>`, meta likewise, rename candidate into place (same fs, mv), compose up, health check, then `docker exec sdtm-rag-api python -m scripts.check_index_freshness` rc=0. Not found → fail BEFORE touching prod with a clear message ("run kb-sync for <ref>").
   - unknown fingerprint (old image) / no matching copy on a manual `tag=` rollback → loud warning; add boolean dispatch input `force_data_mismatch` (default false) to proceed without swapping; otherwise fail.
   - Auto-revert-on-health-failure step must never be blocked by the new check: it restores BOTH image and (if swapped) the previous chroma/meta.
   - `prune`: keep newest 2 `chroma_prev_*`; never touch `chroma_failed_*`.
